## Notes from the analysis

- Three pods: db (PostgreSQL), backend (FastAPI/uvicorn on 8000), and frontend (static Vite build served by nginx on 80). The Traefik proxy, Adminer and Mailcatcher from Compose are not needed, because Nexlayer handles routing and ingress.
- The backend reaches the database at db.pod:5432 (POSTGRES_SERVER=db.pod, POSTGRES_PORT=5432). Never use localhost or the Compose service name 'db'.
- The Compose 'prestart' service (backend/scripts/prestart.sh: wait for DB, alembic upgrade head, create initial superuser) is a one-shot job, not a daemon. Run it in the backend pod's start command before launching uvicorn, e.g. `bash scripts/prestart.sh && fastapi run --workers 4 app/main.py`.
- Backend and frontend images are built from their own Dockerfiles (backend/Dockerfile uses uv; frontend/Dockerfile runs a Bun/Node build then nginx). The listed base images are the mirror.gcr.io equivalents to use in those Dockerfiles.
- VITE_API_URL is baked into the frontend at build time, so set it to the backend pod's public URL before building the frontend image.
- Set BACKEND_CORS_ORIGINS and FRONTEND_HOST to the frontend's public URL so browser calls to the backend pass CORS and email links resolve.
- Do not leave SECRET_KEY, FIRST_SUPERUSER_PASSWORD or POSTGRES_PASSWORD as 'changethis' outside local: the app refuses to start with default secrets when ENVIRONMENT is not local. The Postgres password is generated by Nexlayer and shared with the backend as POSTGRES_PASSWORD.
- The exact file contents of backend/ and frontend/ were not provided, so ports and start commands follow the standard template conventions (backend 8000, frontend nginx 80).
